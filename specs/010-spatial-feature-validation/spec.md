# 010 空间感特征轻量验证与速度—准确率双轨决策

状态：实验已完成（P0/P1/P1b/P1c/P1d/P3/P4/P4b/P4c 已完成；地图候选未发布）
上下文：空间定位；上游地图准备发布 XYZ/法线/位姿契约

## 背景与目标

当前项目已有 RGB 检索、LoFTR/RoMa 匹配、tile XYZ→PnP 和 ACE 法线输入，但“空间感”仍混合了三种不同语义：单目几何输出、LAS 地图几何、定位绝对精度。008 证明 MiDaS 法线直接注入 ACE 不增益；009 的 12 次汇总又包含 10 张 tile，可能因查询与索引同图而高估成功率。

目标是在不训练、不下载大于 2GB 的模型、不改变默认路由的前提下：

1. 固化近年论文、官方代码路径与项目适配判断；
2. 按 P0/P1/P3/P4 完成低成本证伪；
3. 分别给出速度候选与准确性候选，禁止用重投影误差冒充独立真值精度；
4. 为下一轮最小实现提供稳定的几何特征与 benchmark 契约。
5. 用一个小于 200MB 的官方法线权重验证 MiDaS 失败是否来自模型能力，而不是继续扩大集成范围。

## 范围

### In Scope

- P0：复用缓存 MiDaS，在 2 张真实查询 + 3 张 accepted tile 验证输出、耗时和有效率；
- P1：把 LAS 世界法线旋转到相机系，计算与查询法线的有向/无向角残差；复用 008 判断直接 6ch 注入是否有效；
- P3：审计 hloc/ACE0/SCR Priors 的依赖与可运行边界，选 hloc 为首个轻量官方对照；
- P4：拆分真实查询、同图烟测和 leave-one-out，分别报告延迟、重投影诊断、平移/旋转误差；
- P1b：固定 MoGe-2 ViT-S normal 的官方 MoGe-2 代码与 141MB 权重，在同一 2 张真实查询 + 3 张 tile 上验证输出契约、耗时和 LAS 法线角残差；
- P1c：修复地图法线生成的旋转非等变和无效邻域假法线；只为 3 张验证 tile 生成候选副本，不覆盖当前发布资产；
- P1d：把候选扩到 8 个不同空间位置，分别量化 XYZ 监督像素、有效法向输入像素与二者交集；仍只写隔离候选；
- P4b：pose-only 基准不加载只服务 LAS 诊断、坐标转换和视觉产物的 5.2M 稠密点云/KD-Tree；生产默认路径保持完整；
- P4c：pose-only 基准跳过不参与位姿评分的二次 LightGlue 投影拟合诊断；生产默认路径继续执行并返回诊断；
- 研究与决策资产：`research/2026-08-31-spatial-features-lightweight-validation.md`。

### Out of Scope

- 不运行 P2（MASt3R/MoGe 全量定位接入）、不训练/微调任何模型；
- 不下载超过 2GB 的权重或评测集；
- 不改 API、前端、默认算法路由或 PnP 返回契约；
- 不把同源 NPY、自匹配或 LAS 邻近性解释成独立绝对精度；
- 不在本轮接入 ACE0、SCR Priors、VGGT、FreeReg、2D3D-MATR、I2PNet。

## 用户故事

作为定位算法维护者，我希望先用小样本和现有资产排除错误的空间特征接法，再把时间投入能同时改善速度或准确性的候选。

## 验收标准

- **AC-010-01**：研究记录包含 2023–2025 年单目几何、匹配/2D-3D 注册、定位基线的论文与官方代码路径，并区分“论文可行 / 代码可达 / 本项目已验证”。
- **AC-010-02**：P0 报告 2 张真实查询 + 3 张 tile 的输出尺寸、有限值率、法线长度、冷/热耗时与实际 `normal_source`；不得把模型回退当真实输出。
- **AC-010-03**：P1 在显式 `world_to_camera` 变换后计算法线角残差；若无向中位角大于 20°，禁止作为 PnP 硬过滤或默认 6ch 输入。
- **AC-010-04**：P3 明确 hloc/pycolmap、ACE0/DSAC*、SCR Priors 的本地可达性、依赖成本和本轮执行/跳过理由；未运行不得标为通过。
- **AC-010-05**：P4 将真实查询、索引同图烟测和 leave-one-out 分开；速度结论使用延迟，准确性结论只使用独立/留出真值的平移与旋转误差。
- **AC-010-06**：本轮不改变默认路由；规格校验、相关快速测试与漂移检查通过，已知未完成项保持未勾选。
- **AC-010-07**：MoGe-2 候选必须报告官方来源、固定代码版本、权重体积、坐标系、5 张样本的有限值率与耗时；仅当 3 张 tile 的相机系无向角总体中位数 ≤20° 时才允许进入后续软评分，否则记录证伪并停止接入。
- **AC-010-08**：地图法线生成必须只在中心和上下左右邻域均有效时输出单位法线，并对同一 XYZ 的刚体旋转保持等变；合成斜面最大无向角误差 ≤0.01°、孔洞/边界不得产生假有效法线，3 张真实 tile 只写候选副本并报告覆盖率和旧新角差。
- **AC-010-09**：从 accepted 地图中均匀选取 8 个不同 `tile` 空间位置，生成隔离候选并报告 XYZ 监督像素、已发布/候选有效法向像素及其与 XYZ 的交集；必须依据 ACE 代码说明监督掩码是否变化，并继续报告 MoGe 无向角门，不运行训练、不覆盖 `tile_index.json` 或已发布法线。
- **AC-010-10**：正式 `scripts/benchmark_010.py --pose-only` 配置（无位姿先验）不得加载 5.2M 稠密点云或构建点云 KD-Tree，并将 LAS 验证显式标记为跳过；默认生产路径仍加载完整地图。相同 8+2 位姿基准的逐条位姿、重投影和质量门不得漂移，冷启动延迟相对上一 pose-only 报告至少降低 40%。
- **AC-010-11**：正式 pose-only 配置不得调用用于 `projection_verification` 的二次 LightGlue 匹配，并将该字段显式标记为跳过；默认生产路径仍执行投影拟合。正式对照必须把既有 `ransac_seed` 实际传入每次 PnP RANSAC，以排除随机采样噪声；相同 8+2 的成功、质量门、内点、PnP 重投影与位姿误差逐条不得漂移，cold 和留一 warm P50 至少一项相对 P4b 再降低 20%。

## 成功标准

- 除已完成 hloc 前端外，几何候选只允许新增一个 ≤200MB 的官方权重且无训练；
- 5 张 P0 样本全部得到真实 MiDaS 输出，热态增量可量化；
- 至少得到 1 张 leave-one-out 位姿误差烟测，且不把它扩展为总体承诺；
- 速度路线与准确性路线各有下一步门槛，而非单一“成功率”排名。
- MoGe-2 验证不改 API、默认路由或 PnP，对门槛失败可完整回滚。
- 地图法线修复不覆盖 `tile_index.json` 当前引用的资产，验证通过后仍需独立发布授权。
- 8 位置扩展只用于覆盖与精度决策；无论结果如何都不自动触发重训或发布。
