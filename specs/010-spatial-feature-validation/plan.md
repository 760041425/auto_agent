# 010 验证计划

## 上下文与依赖

- 地图准备拥有 `MapTile.image_path/npy_path/normal_path/camera_pose`；
- 空间定位只消费 accepted MapTile，并在适配边界完成世界系→相机系变换；
- 外部几何模型只输出带来源、坐标系、深度语义和置信度的内部契约，不向领域层泄露张量/模型异常。

## 批次 P0：资产与输出可达性（已完成）

1. 固定 2 张真实查询 + 前 3 张 accepted tile；
2. 运行缓存 MiDaS，记录冷/热耗时、shape、有限值率、法线长度和值域；
3. 依赖不存在或回退常量时，本批次失败，不把 fallback 计入有效样本。

## 批次 P1：几何对齐证伪（已完成初验）

1. 读取 tile 世界法线与 `world_to_camera_wxyz`；
2. 计算 `n_map_camera = R_cw n_map_world`；
3. 计算有向与无向角误差，另做一次相对逆深度取倒数敏感性检查；
4. 门槛：无向中位角 ≤20° 才可进入软评分，≤10° 且留出基准增益才允许硬过滤；
5. 当前 29.43°–51.06°，停止接入。

## 批次 P1b：小模型法线候选（已完成）

1. 固定官方 MoGe-2 代码版本，避开当前 MoGe 3 在 macOS 上不可用的 Triton/FlexGEMM 路径；
2. 只下载 `Ruicheng/moge-2-vits-normal`（35M 参数、约 141MB），Metric3Dv2 保留为候补，不同时安装；
3. 先以领域函数固化“3 张 tile 总体无向角中位数 ≤20° 才可进入软评分”的门槛，再运行 2 真实 + 3 tile；
4. 记录 `normal_source`、OpenCV 相机坐标系、shape、有限值率、法线长度、设备与冷/热耗时；
5. 门槛失败立即停止，不修改定位链路；门槛通过也只生成下一独立 TL-ID，不在本切片直接集成。

实跑结果：5/5 有限输出，热态 P50 约 1.02s；对已发布法线总体 52.79°。P1c 修正 raw XYZ 四邻域后为 33.47°，仍未过 20°；已发布法线与修正候选相差 25.57°，不继续安装模型。

## 批次 P1c：地图法线参考修复（已完成）

1. TL-010-13 Red：合成斜面加孔洞，证明当前按轴 min-max 双边滤波不满足旋转等变，且跨无效邻域产生假法线；
2. Green：改为对原始世界 XYZ 做有效四邻域中心差分，只在完整 stencil 且叉积非退化时归一化；
3. 扩散检索所有按轴归一化平滑、中心差分法线和跨无效邻域写法；同模式一并处理；
4. 从 yaw90/yaw180/yaw270 三张 XYZ 生成隔离候选法线到 `projections/benchmark_010_map_normals/`，不覆盖 `normal_path`；
5. 报告旧/新法线角差、覆盖率、生成耗时，并用新参考重跑 MoGe 三 tile 角度；仍大于 20°则保持停止。

回滚：恢复 `_compute_normal_map` 旧实现并删除隔离候选目录；当前 `tile_index.json` 和生产法线文件始终不变。

结果：合成旋转最大误差 `1.57e-6°`、假法线 0；3 tile 候选生成 P50 0.0238s，旧/新总体中位角 25.57°。MoGe 对新参考为 33.47°，仍拒绝软评分。候选只写隔离目录，发布资产未变。

## 批次 P1d：8 位置覆盖与 ACE 输入影响（已完成）

1. TL-010-14 Red：领域汇总必须拒绝少于 8 个不同 tile，并把 XYZ 监督像素与法向有效输入分开；
2. Green：均匀抽取 8 个不同 `tile`，按 ACE 的 1/8 最近邻采样口径统计 XYZ 监督量、已发布/候选有效法向输入及交集；
3. 为 8 个位置生成隔离候选，复跑 MoGe 角误差门，报告空间位置数、覆盖变化、生成/推理耗时；
4. 不修改 `tile_index.json`，不覆盖已发布法线，不训练 ACE；结果只支持“是否值得另开训练/发布切片”的决策。

回滚：删除 `projections/benchmark_010_map_normals_8/` 和对应报告；生产资产与默认路由不受影响。

结果：8 个不同位置、16,396 个 ACE XYZ 监督像素保持不变；监督点上的法向信息覆盖从 91.94% 降到 78.21%。MoGe 对候选总体无向角中位数 40.33°，未过 20° 门；不训练、不发布、不切路由。

## 批次 P4b：pose-only 稠密点云冷启动消除（已完成）

1. TL-010-15 Red：后处理计划必须把稠密点云和 LAS 验证纳入 pose-only 跳过契约，默认计划保持启用；
2. Green：只有计划需要坐标转换、视觉产物或 LAS 验证时才调用 `load_colmap/get_point_cloud_arrays`；跳过时使用空引用且不得触达加载器；
3. L2 以加载器哨兵验证 pose-only 不触达 5.2M 点路径；L3 用相同 8+2 数据复跑，和 `reports/benchmark_010_pose_only.json` 逐条比对位姿、重投影、质量门；
4. 性能门：cold 22.473s 至少下降 40%，warm 延迟不得显著恶化；生产默认行为保持完整。

回滚：恢复定位入口无条件加载点云，并移除后处理计划新增字段；不涉及资产格式或模型变更。

结果：5,252,140 点/KD-Tree 初始化实测 14.405s；正式 8+2 优化后 cold `22.473s→6.578s`（-70.7%），leave-one-out warm P50 `5.410s→4.829s`（-10.7%）。成功、质量门、内点、重投影逐条一致，平移/旋转最大漂移均为 0；10/10 LAS 诊断显式 skipped。

## 批次 P4c：pose-only 二次投影拟合诊断消除（已完成）

1. TL-010-16 Red：后处理计划必须在 pose-only 关闭 `projection_verification`，默认计划保持启用；
2. Green：最终位姿确定后，仅在计划启用时执行二次 DISK+LightGlue 与 homography/NPY 诊断；跳过时返回显式状态；
3. 基准报告记录每条投影诊断状态；修复焦距搜索已声明但未生效的 `ransac_seed`，用相同种子分别生成“启用/跳过投影诊断”的 8+2 对照，再逐条比对成功、质量、内点、重投影和位姿误差；
4. 性能门：cold 或 leave-one-out warm P50 至少一项相对 P4b 降低 20%，默认完整路径 smoke 仍产生可用投影诊断。

回滚：恢复投影验证无条件执行，并移除计划字段；不涉及模型、资产或 API 结构迁移。

结果：同种子投影启用控制组与正式跳过组的 10 条成功、质量门、内点、PnP 重投影和位姿误差逐字段差异为 0；正式报告 10/10 `projection_verification` 显式 skipped。相对 P4b，cold `6.578s→2.301s`（-65.0%）、leave-one-out warm P50 `4.829s→0.675s`（-86.0%）；相对同种子控制组，cold `3.483s→2.301s`（-33.9%）、warm P50 `1.422s→0.675s`（-52.5%）。默认路径 smoke 仍得到投影拟合、LAS 100%、坐标 ready 和 3 个视觉产物。
