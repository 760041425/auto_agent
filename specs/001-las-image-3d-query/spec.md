# 001 LAS 影像 3D 查询

状态：基线补录
上下文：任务与影像、地图准备、空间定位

## 背景与目标

用户需要把现实查询影像关联到 LAS 地图，在 Web/API 中管理影像和比较任务，并从匹配结果读取地图坐标系中的三维坐标与诊断证据。本规格把存量能力转成可追踪的验收基线，不等同于宣告所有行为已经验证。

## 范围

### In Scope

- 查询影像上传、列表、详情与删除；
- 显式触发地图预处理并查询进度；
- 创建比较任务、查询任务状态和读取报告；
- 由地图投影及其坐标图建立影像区域到三维坐标的对应；
- 对资源缺失、无匹配和处理失败返回可诊断结果。

### Out of Scope

- 自动监视目录并在新增 LAS 后触发处理；
- 多租户、权限、云端弹性调度和生产级持久队列；
- 把地图 `x/y/z` 在没有坐标参考定义时称为经度、纬度、海拔；
- 所有 LAS point format 和所有外部渲染器的兼容承诺。

## 用户故事

- 作为测试人员，我能上传并找到查询影像，以便发起比较。
- 作为地图工程人员，我能显式运行预处理并看到进度或失败原因。
- 作为算法使用者，我能获得匹配坐标、置信度和验证证据，以便复核结果。

## 验收标准

- **AC-001-01**：上传有效影像后返回稳定 ID、文件名和状态，列表与详情能读取同一记录。
- **AC-001-02**：查询不存在的影像或以不存在影像创建任务时返回明确 4xx，不启动后台工作。
- **AC-001-03**：比较任务具有 `pending → processing → completed|failed` 的可观察状态；完成后报告与任务一一对应。
- **AC-001-04**：预处理由 API 显式触发；状态接口暴露运行标记、进度、步骤、完成时间或错误，重复触发不会并行启动同一流程。
- **AC-001-05**：成功报告至少包含是否匹配、匹配数量、置信度、区域信息和可选中心 `x/y/z`；坐标参考必须由地图配置或契约说明。
- **AC-001-06**：无 LAS、无投影、无匹配或算法异常时，任务/预处理进入失败状态并保留可理解错误，不生成伪成功报告。

## 成功标准

- 每条验收标准在 `testlist.md` 中至少有一个场景；
- 快速测试不依赖真实大 LAS、模型下载、GPU 或外部渲染器；
- 规格、任务、测试和实现映射可由追踪脚本生成。
