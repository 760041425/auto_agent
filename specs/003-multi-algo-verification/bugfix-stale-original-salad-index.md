# BUG-003-04 — 原版 SALAD 加载跨版本旧缓存后返回 0 候选

日期：2026-08-01  
状态：已修复

## 1. 期望与实际

- 期望：SALAD+RoMa（原版）在当前地图有效瓦片中完成全局检索并返回 top-K 候选。
- 实际：日志显示 `tile_index.json` 有 18,528 条记录，加载 245 条缓存后立即得到 0 候选。

## 2. 复现矩阵

| 环境/版本 | 输入与路径 | 预期 | 实际 | 证据 |
| --- | --- | --- | --- | --- |
| macOS/MPS，2026-08-01 | `d7393932-3f76-4de4-808a-d5a3266c1c2b.jpg`，SALAD+RoMa 原版 | 至少一个检索候选 | 0 候选，定位提前失败 | 用户日志 23:22:59；本地缓存清单 |

## 3. 根因分析

### 3.1 5 Why

1. 为什么没有候选？检索阶段没有任何 tile 同时拥有当前记录和缓存描述子。
2. 为什么没有交集？旧 `salad_index.npz` 的 245 个 key 不含 pitch；当前有效瓦片 key 包含 `_p-30/_p-15/_p+0/_p+15`。
3. 为什么仍报告索引加载成功？加载器只校验 NPZ 能否解码和条目数非零，未校验当前 tile key 覆盖。
4. 为什么没有自动恢复？缓存存在时函数直接返回，既不尝试兼容 V2 缓存也不重建。
5. 根因：描述子缓存契约缺少地图/tile 版本兼容性校验，导致“文件可读”被误当成“索引可用”。

真实路径复放同时发现：原版 runner 从模块导入初始为 `None` 的 `_POINT_INDEX`，随后 `load_colmap()` 虽更新模块属性，局部绑定仍保持 `None`；常驻服务的预热状态掩盖了该 clean-process 缺陷。主路径改为只使用 `get_point_cloud_arrays()` 的返回值。

继续复放发现 `_roma_match()` 实际直接调用 `_lightglue_match()`；因此日志虽写“RoMa 匹配”，执行的却是 DISK+LightGlue，违反算法 ID/标签契约。这也是候选恢复后必须一并修复的直接路径缺陷。

### 3.2 为什么未被测试/监控发现

- 单元测试只覆盖位姿选择和 V2 算法工具，没有跨版本缓存夹具。
- 日志分别打印 tile 总数与缓存条数，但没有打印交集/覆盖率，也没有将零交集判为缓存失效。

## 4. 影响面

- 直接影响 `salad_roma` 原版检索，以及复用 `_salad_retrieve` 的原版派生路径。
- V2 使用独立 `salad_index_v2.npz` 与 `_tile_key`，当前 8,550 条有效 key 正常，不受直接影响。

## 5. 修复方案

1. 从当前 `tile_index.json` 提取非空、文件存在的有效 key。
2. 加载原版缓存后校验 key 交集；零交集或描述子维度不兼容即拒绝。
3. 尝试读取 V2 缓存的 `multi` 描述子供原版使用；保持原版查询描述子与排序逻辑不变。
4. 两份缓存均不可用时重建原版缓存，并输出明确诊断日志。
5. 恢复 TinyRoMa 的张量输入、稠密 warp 采样与像素坐标转换；迭代精炼阶段仍可按原流程使用 LightGlue，但首轮 `salad_roma` 候选匹配不得替换算法。
6. 原版成功结果生成查询图、最终位姿 XYZ NPY 和 H，并以严格 `<0.3m` 坐标差覆盖高内点可信判断。

## 7. 回归测试

- Red 1：导入 `_select_compatible_salad_cache` 时收集失败，证明旧实现没有缓存兼容性边界。
- Green 1：旧 key 零交集时选择 V2 `multi`，夹具测试通过。
- Red 2：把 `_lightglue_match` 设为调用即失败后，`_roma_match` 触发该失败，证明 RoMa 标签实际跑了 LightGlue。
- Green 2：TinyRoMa `match → sample → to_pixel_coordinates` 适配测试通过，LightGlue 未被调用。
- Red/Green 3：607 高内点夹具最初没有坐标可信适配器；实现后坐标差失败会强制 `reliable=false`。

## 8. 风险与回滚

- 风险：错误选用维度不兼容描述子；通过维度与有限值校验防止。
- 回滚：移除兼容缓存回退，显式重建 `salad_index.npz`。

## 9. Before/After

- Before：245 条旧缓存与当前有效 tile key 交集为 0，返回 0 候选。
- After：同输入在 clean process 中加载 `8550/8550` 条 `v2_multi` 缓存，返回 3 个候选；TinyRoMa 每个候选采样 3,000 点。最终复核得到 640 个 PnP 内点、位姿 `[21.491, 1.683, 1.636]`，同时坐标中位差为 `7.563m`（P95 `188.578m`），所以返回 `success=true, reliable=false`，并生成查询图、重投影图、对比图和 XYZ NPY。

## 10. Changelog

- 原版缓存增加当前 tile key/描述子维度/有限值校验和 V2 `multi` 回退。
- 原版恢复真实 TinyRoMa 局部匹配；日志和失败原因不再误写 LightGlue。
- clean-process 点云读取改用函数返回值，迭代轮次恢复服从 `max_iterations` 参数。
- 原版接入与 V2 相同的严格 `<0.3m` 最终可信门槛；高内点不再覆盖坐标差失败。
