# 003 决策记录

Phase A 决策已随本轮“开始修复”授权实施；涉及真值、硬件和最终推荐的 Phase B 决策标记为 TODO（暂时遗留）。

## DEC-003-01：算法 ID 直接映射 runner

- 状态：已实施
- 背景：当前 `algorithm_id → matcher 字符串 → if/elif` 两次映射已经发生漂移。
- 决定：以稳定算法 ID 为注册表主键，注册项直接持有 runner 和能力元数据。
- 替代：修正现有字符串条件。
- 后果：增加一个小型应用层注册表，但消除路由分派重复和 benchmark 直调旁路。

## DEC-003-02：区分求解成功与结果可靠

- 状态：已实施（Phase A）
- 背景：当前 4–7 个内点也可能返回 `success=true`，与 `min_inliers=12` 冲突。
- 决定：`success` 表示产出几何解，`reliable` 表示达到批准门槛；UI 同时展示。旧算法暂兼容内点门槛，V2 后续由 DEC-003-08 的坐标差判据覆盖。
- 替代：低于门槛直接返回失败。
- 后果：保留算法诊断价值，同时避免把低质量位姿当可信结果；需要兼容旧前端。

## DEC-003-03：只有独立真值产生绝对精度

- 状态：Phase A 已实施；真值来源为 TODO（暂时遗留）
- 背景：同一 NPY、同一匹配或同一地图派生的比较存在循环验证。
- 决定：绝对定位精度只来自独立相机位姿或控制点；其他指标按一致性/拟合/邻近性命名。
- 替代：继续使用当前 `verify_err_m`。
- 后果：短期可能没有可报告的米级精度，但结论可审计。

## DEC-003-04：API 与 benchmark 共用运行入口

- 状态：已实施
- 背景：benchmark 直调新实现而 API 走旧路径，造成“脚本可运行、产品不可运行”。
- 决定：两者都调用注册表 runner；benchmark 只负责数据集编排和统计。
- 替代：分别维护两套分派。
- 后果：产品与实验路径一致，算法变更需满足同一契约。

## DEC-003-05：报告按 run_id 管理

- 状态：已实施
- 背景：多个 `final` 文件无法判断权威性和生成条件。
- 决定：使用 `<timestamp>-<uuid>` 形式唯一 run_id，另存稳定 `config_hash`，输出 manifest/results/report；权威摘要显式引用 run_id。
- 替代：继续覆盖固定文件名。
- 后果：可追溯性提高，需要生成物清理和保留策略。

## DEC-003-06：分阶段交付

- 状态：已实施（Phase A）；Phase B 标记 TODO（暂时遗留）
- 背景：运行正确性可以独立修复，算法推荐受真值和数据集阻塞。
- 决定：Phase A 先交付正确分派、统一契约和运行稳定性；Phase B 再交付可信精度与推荐。
- 替代：等待所有研究问题解决后一次性交付。
- 后果：P0 风险更早解除，Phase A 不得宣称最终算法结论。

## DEC-003-07：坐标交叉验证与绝对位姿 Benchmark 分层

- 状态：已实施
- 背景：参考实现位于 `slam-map`，但空间定位功能不应要求另一应用及其 camera 数据库同时运行。
- 决定：把坐标转换迁入本上下文：V2 runner 保存最终 2D–3D 内点、拟合 query→SLAM XY 的 H，并用最终位姿生成查询图空间 XYZ NPY；API 只消费所属任务产物。继续保留像素拟合、本地 H/NPY 坐标交叉验证、独立 holdout 位姿 Benchmark 三层语义。
- 后果：页面选点无需网络或 camera 记录；历史任务没有新增产物，必须重新定位。只有独立真值层能声明绝对定位精度。

## DEC-003-08：具备最终坐标产物的定位结果只由多点坐标差决定可信状态

- 状态：已实施
- 背景：以 `min_inliers` 判定可信会出现“22 内点但 H/NPY 坐标差几十米仍显示可信”的错误结论；用户明确要求最终标准使用该差值，不使用点数或相似度。
- 决定：在最终 NPY 的有效像素中确定性采样最多 256 点，以 H→SLAM XYZ 与 NPY XYZ 的三维差中位数为最终判据。用户确认严格门槛为 `<0.3 m`，等于或超过均不准；没有可用坐标差时 V2 与 SALAD+RoMa（原版）一律低可信。
- 后果：内点和相似度仅帮助诊断求解过程；它们不能覆盖坐标差失败。该标准是产品内部一致性验收，不改名为独立真值绝对精度。

## DEC-003-09：一致性判据必须包含 Z 维度

- 状态：已实施（2026-08-03）
- 背景：`evaluate_local_coordinate_consistency()` 只比较 XY 平面距离，高度异常位姿会被错误判为 `reliable=true`
- 决定：计算三维欧氏距离 `slam_xyz=(slam_x, slam_y, 0)` vs `npy_xyz=NPY XYZ`，与 `query_local_coordinate_transform` 单点查询语义一致
- 替代：保持 XY-only 但增加独立的 Z 判据
- 后果：更多位姿因高度偏差被判为 `reliable=false`，这是正确行为（之前是假阳性）

## DEC-003-10：精化步骤复用初始匹配器

- 状态：已实施（2026-08-03）
- 背景：`refine_pose_with_roma()` 硬编码 LightGlue，与初始 SALAD+RoMa 使用的 TinyRoMa 不一致，位姿偏差大时精化失败
- 决定：增加 `matcher_type` 参数分派到 TinyRoMa/LightGlue；API 端点从 `match_method` 推导（salad_roma→tiny_roma）
- 替代：保持 LightGlue 但增加匹配数阈值
- 后果：SALAD+RoMa 路径精化成功率提高；其他算法保持 LightGlue 作为默认回退

## DEC-003-11：原版 SALAD 复用兼容的 V2 多模态描述子缓存

- 状态：已实施
- 背景：原版 `salad_index.npz` 只有旧式无 pitch key，当前 `tile_index.json` 使用多俯仰 key；缓存可读取但与有效 tile 零交集，检索静默返回 0 候选。
- 决定：缓存加载必须按当前有效 tile key 校验；原版优先使用自身兼容缓存，自身缓存不兼容时复用 `salad_index_v2.npz` 中同维度的 `multi` 描述子，仍以查询端 RGB+零填充的原版描述子计算相似度。
- 后果：避免重复构建 8,550 条同维度描述子；不改变原版/V2 的算法边界。两份缓存都不兼容时执行原版重建。
