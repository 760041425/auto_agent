# 002 实施计划

## 目标数据流

```text
LAS/轨迹/COLMAP
  → 地图准备：投影 + XYZ/法线 + 位姿 + 版本化索引
  → 空间定位：候选检索 → 选择匹配/回归路径 → PnP → 质量评估
  → 任务与影像：持久化任务状态与算法结果
  → API/Web：展示可比较结果和诊断证据
```

## 设计边界

- `LocalizationRequest` 只表达影像、算法和可验证参数；
- `LocalizationResult` 统一成功、失败、位姿和质量，不暴露模型对象；
- `PoseQuality` 封装内点数、重投影误差、置信度与优选规则；
- 模型加载、设备选择、文件缓存和 NumPy/Torch 转换属于基础设施适配。

## 增量阶段

1. **契约固定**：为算法注册、任务恢复、结果格式和优选规则补测试；
2. **地图资产**：验证 tile 索引中投影、XYZ/法线和位姿的一致性；
3. **算法路径**：分别验证 LightGlue、RoMa、ACE 的成功与失败隔离；
4. **基准设施**：固定输入集、预热和计时边界，输出可比较报告；
5. **阈值决策**：根据目标硬件批准实时阈值，再决定默认算法和降级路径。

## 变更点

| 模块 | 计划 |
| --- | --- |
| `api/routes/localize.py` | 将算法校验、任务编排和结果映射逐步抽离为应用用例 |
| `services/localizer/salad_roma.py` | 保留算法适配，避免其定义任务状态和 API 契约 |
| `services/localizer/ace_trainer.py` | 分离训练与推理模型加载责任 |
| `services/las_processor/` | 发布可校验的地图资产契约和版本信息 |
| `tests/` | 增加契约、恢复、算法隔离和基准测试 |

## 回滚

- 新算法路径可从注册表移除，保留原可用路径；
- 新地图索引应保留版本并允许读取上一个兼容版本；
- 性能优化不得改变结果契约；若质量退化则回退默认算法，而不是修改验收口径。
