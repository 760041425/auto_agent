# 规格包模板

## `spec.md`

```markdown
# <ID> <标题>

状态：草案 / 已批准 / 实施中 / 已完成
上下文：<bounded context>

## 背景与目标
## 范围
### In Scope
### Out of Scope
## 用户故事
## 验收标准
- **AC-<ID>-01**：<可观察行为>
## 成功标准
## 关联
```

## `clarify.md`

使用表格记录 `ID / 问题 / 结论或假设 / 状态 / 决策人`。开放项必须说明是否阻塞。

## `plan.md`

包含上下文分配、依赖方向、数据/接口契约、迁移顺序、验证策略和回滚。领域规则不能只落在路由或 DTO。

## `tasks.md`

每项使用 `TASK-<ID>-NN`，写清依赖、预期文件/行为和完成证据。未完成项不得提前勾选。

## `testlist.md`

每项使用 `TL-<ID>-NN` 并映射 AC。至少覆盖：

- 主路径；
- 输入与资源不存在；
- 边界值和空值；
- 权限、并发、幂等与恢复（适用时）；
- 契约兼容与失败诊断；
- 性能/安全等非功能要求（适用时）。

追踪表、任务、测试名和报告中始终写完整 `AC-<ID>-NN`，不得缩写为 `AC-01` 或只写序号。

## `checklist.md`

分别列 Definition of Ready 和 Definition of Done。环境未验证、性能未测量或全量测试未运行必须保持未勾选。

## `risks.md`

使用 `RISK-<ID>-NN`，记录概率/影响、触发信号、缓解和回滚。

## `decisions.md`

每个决定记录状态、背景、决定、替代方案和后果。不要把仍开放的问题写成“接受”。
